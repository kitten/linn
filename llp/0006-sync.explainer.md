# LLP 0006: SSH synchronization

**Type:** Explainer\
**Status:** Active\
**Systems:** Sync, Store, CLI\
**Related:** LLP 0000, LLP 0001, LLP 0004

## Boundaries

Sync is explicit replication of original records and permanent deletions.
There is no central server, background daemon or device identity. Both machines
install Linn; SSH authenticates the account. Writer email is preserved metadata,
not authentication. Pair only accounts trusted to read and modify the selected
store. Removing a remote stops future exchanges; it cannot retract copies.

## Commands

- `sync:remote pair <name> <origin> [--scope <repository>]` saves a new remote in
  the selected store; it does not connect or verify reachability. `sync` performs
  the connection. A duplicate name is an error naming the remote and the removal
  command; remove it before replacing.
- `sync:remote remove <name>` removes that configuration, not data.
- `sync:remote list` lists names, origins and optional scopes.
- `sync:serve [--stdio]` serves the protocol on stdin/stdout until EOF. Stdio is
  the default and only transport endpoint; no listening socket is opened.
- `sync` pulls every configured remote in name order, publishes local indexes,
  then pushes the merged store to every remote in name order. A failed pull
  prevents the push phase. Publish any successfully received local records before
  returning that error, so an unavailable peer does not leave local reads blocked.
  If publication itself fails, report both failures and the rebuild command.
  Errors identify the peer and direction. A failed push stops the run; earlier
  transfers remain durable and rerunning is safe. No remotes is a successful
  no-op except that pending local publication is still repaired.

Origins are `ssh://[user@]host[:port][/absolute/store/path]`. Omitted paths use
normal remote store resolution. SSH aliases work. Percent escapes, passwords,
queries and fragments are rejected rather than interpreted. Paths are absolute;
spaces and quotes are safely shell-quoted. Use the SSH configuration for keys,
proxy jumps and aliases. Invoke `ssh -T` with batch authentication, connection
and keepalive timeouts, normal host-key checking, and a fixed remote command
`linn [--store <path>] sync:serve --stdio`. No local shell evaluates the origin.
Diagnostics remain stderr; protocol bytes alone use stdout. CLI sync success
prints transfer counts (or JSON), without per-peer or publication progress
messages; failure uses the normal error exit code 2.

## Merge and publication

Schema migration 4 adds local remote configuration and a pending-publication marker
shared by local writes and sync (LLP 0001).
Configuration never replicates. Exchange original envelope bytes and their
SHA-256, body SHA-256, and tombstone IDs; never copy SQL files, indexes, vectors or
source files. Validate hashes and envelope ID before accepting a record. Unknown
JSON fields remain in the immutable envelope but are not indexed as author terms.
Rebuild preserves existing envelopes byte for byte. Existing ID and identical
envelope hash is a no-op; different hashes are an explicit conflict, never a
last-writer-wins overwrite. Tombstones always win and are never garbage collected.
Close envelopes, parent references and writer metadata travel unchanged.

An optional scope is an exact original-scope match, using SQLite ASCII case-insensitivity, applied to
records in both directions. It is an exchange selection, not an authorization
boundary: the remote SSH account has access to its whole store. Cross-scope
references remain unresolved unless independently present; no referenced body
is implicitly disclosed. Tombstone IDs travel regardless of scope so a forgotten
record cannot return after scope changes; they contain no body or attribution.
Use a dedicated store/account when access itself must be restricted.

Each received item commits atomically with a pending marker. Forget deletes
sections and original records using secure deletion and FTS segment merging.
When no sections remain, reset the external-content FTS index with `delete-all`
before optimizing, including its empty-index accounting.
A completed transfer rebuilds derived indexes once if anything changed, then
clears the marker. A crash or indexing failure leaves originals durable and
blocks ordinary store opens with instructions to run `index:rebuild` or sync.
Check the pending marker inside the same pinned read transaction that supplies
the source version and catalog/index reads. An import committed before this
snapshot must block the open; a later import must not mix into its reads.
Sync resumes from originals and tombstones, not an acknowledgement cursor.
Rebuilding may recompute the documented lifecycle projection, just as explicit
rebuild does. Concurrent writers are serialized by SQL write transactions;
publication uses the existing source-version check. A sync is not a distributed
transaction: concurrent changes can require another run to converge.

## Wire protocol

Protocol version 1 is sequential, newline-delimited JSON, at most 16 MiB per
frame. Every connection starts with a version handshake; incompatible peers
fail before transfer. Inventory pages contain at most 256 IDs/hashes, ordered
by ID with an exclusive keyset cursor. Tombstones are transferred before records.
Only missing records need body transfer; unchanged records do not. A conflicting
hash fails immediately without transferring a replacement body.
One envelope is transferred at a time. Oversized records fail explicitly, never
truncate. Replies are typed success values or an error; malformed, oversized or
truncated input fails. EOF ends the session; `finish` publishes pending indexes.
Requests are hello, inventory, get, needs, apply and finish. Inventories are bounded reads,
not permanent in-memory copies. No network operation occurs on search or ingest.

## Verification

Corpus-free tests cover raw-byte preservation, idempotence, tombstone precedence,
conflicts, scope selection, interrupted publication, version mismatch, bounded
frames, SSH argument quoting and three-store pull-before-push distribution.
Existing retrieval pages must stay identical on unchanged stores.

## File export and import

`export` writes a versioned JSONL bundle; `import <file|->` merges it without
changing IDs, original envelope/body bytes, timestamps, scope or writer attribution.
This is distinct from `add`, which creates a new record from original text.
Imports use the same immutable conflicts, tombstone precedence and publication
rules as sync. Only import bundles from trusted writers: deletions are permanent.

Export defaults to current word-eligible records at one captured UTC clock.
`--all-states` includes candidates, expired records, close envelopes and version
history. Filters are ANDed: `--scope` matches original scope with SQLite NOCASE;
`--kind note|doc`; `--since` is an inclusive creation timestamp, accepting RFC3339
or a positive whole duration in m/h/d/w relative to that clock; repeatable
`--id <ref>` selects the union of resolved whole-record references. No ranked
search selects exports. A fetch reference exports its whole record, not its span.
Unknown references are errors; known records excluded by another filter yield
no item. References use the ordinary caller-scope resolution rule.

Selection is a consistent SQL snapshot. References and lifecycle edges do not
implicitly export other bodies. A history selection containing a closed or
superseded record must also contain at least one accepted envelope or child that
keeps it hidden; otherwise fail and request a broader selection. A stale hidden
projection with no surviving witness requires `index:rebuild` first.
Unresolved outbound references stay unresolved at the recipient.

Only an unfiltered `--all-states` export includes all tombstones, making it the
complete original-data backup. A filtered export cannot recover the scope, kind
or creation date of a deleted record; it never guesses or leaks unrelated IDs.
Explicit tombstone IDs can be exported with `--all-states --id` when no scope,
kind or since filter is supplied. Other exports omit tombstones. Export is a
snapshot, not ongoing deletion delivery; use sync for that purpose.

Bundle version 1 has a header `{"format":"linn-export","version":1}`, then
tagged `item` frames containing the sync Item fields, then an `end` frame with
the item count and SHA-256 of the exact item lines including newlines. Tombstones
precede records; each group is ID-ordered. Each line is bounded to 16 MiB.
The end frame is mandatory and trailing content is rejected. Original envelopes
are strings inside frames, preserving formatting and unknown fields unchanged.
No SQL indexes, vectors, remote configuration or source files travel.

Export stages into a private temporary file before releasing bytes; an error
does not emit a partial bundle. `--output <file>` creates a new mode-0600 file,
refusing existing paths; omission or `-` writes stdout. Import stages and checks
the complete framing, count, digest and every item hash before any merge.
A conflict during merge can leave earlier items committed; publish those before
returning the error, naming recovery if publication also fails. Retry is safe.
Successful import publishes indexes once and reports changed/unchanged item
counts (JSON with `--json`). Export always emits the bundle format regardless
of `--json`; errors go to stderr, with no routine exported-item count. Empty
bundles succeed.
